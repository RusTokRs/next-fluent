## Что делать с открытыми пунктами

Открытых находок нет: V6 закрыт целиком (V6-01…V6-09 исправлены кодом с
регрессионными тестами, 13 из 16 новых тестов падают на коде до правок), V5
закрыт целиком (включая V5-06, V5-10…V5-12 из второго захода), хвост V4-16
закрыт интеграционным прогоном на Next 15 и 16 (см. V5 §5a), оба внекодовых
пункта V3 закрыты тогда же:

- **политика версий** — сформулирована в `SECURITY.md` (патч не меняет
  наблюдаемое поведение, минор может ломать при major = 0, каждое ломающее
  изменение — отдельным заголовком в `CHANGELOG.md`, с 1.0.0 — строгий
  SemVer);
- **воркфлоу публикации** — `.github/workflows/publish.yml`: GitHub Release →
  полный `npm run check` → `npm publish --provenance`; вручную — dry-run по
  умолчанию. Порядок описан в README («Releasing»).

Что осталось непроверенным и вынесено в V6 §8: браузерные прогоны
(`test:next:browser`, `test:next:domains`) локально по-прежнему недоступны (нет
Chromium) и подтверждаются CI PR #7; запас клиентского бюджета после правок V6 —
0.3 kB min / 0.4 kB gzip (бюджет поднят осознанно, замеры в V6 §6); первый
вживую запущенный `publish.yml` — отдельная задача.

## Как читать проход

1. **Резюме** — сколько находок и сколько исправлено.
2. **Методика** — какие команды реально прогонялись: без этого списка отчёт
   невозможно проверить.
3. **Находки по приоритетам** — P1 (неверный результат / блокировка сценария),
   P2 (архитектура и функциональные пробелы), P3 (качество, доки, гигиена).
   У каждой — воспроизведение, а не описание.
4. **«Что проверено и оказалось в порядке»** — список атак и проверок, которые
   устояли: его нужно перечитывать перед следующим проходом, чтобы не искать
   то же самое дважды.
5. **Изменения прохода** — какие файлы правились и чем это проверено.
