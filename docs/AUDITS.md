## Что делать с открытыми пунктами

Открытых находок нет: V16 закрыт целиком (сценарии вместо покрытия дали два настоящих дефекта в слое, который четыре прохода читался как проверенный: `trustedHosts` выключался одним заголовком `x-forwarded-host`, а `Host: example.com:443` отвергался как чужой, потому что парсер URL отбрасывает порт по умолчанию; закрыт пропуск `prefetch` на однодоменном сайте и добавлен гейт «каждый URL навигации каноничен для middleware»; CDN-сценарий и `basePath` + домены проверены и дефектов не выявили), V15 закрыт целиком (самообманка прошлых отчётов
исправлена: `client.js` объявлялся недостижимым в Node, а на деле требовал
рендерера только для тел `useEffect` — ветви провайдера, готовый бандл вместо
исходного текста, один `fallbackBundles` против массива, `className` у
`<FormattedMessage>` — обычный код рендера, который просто не был проверен;
закрыт запасной путь разрешения namespace, когда вызов стоит раньше связывания;
`middleware.ts` перечитан построчно — находок нет, все его инварианты уже
покрыты; три оставшиеся строки `client.js` записаны явно как решение, а не как
хвост: для них нужно решение владельца про `jsdom` или браузерный гейт), V14 закрыт целиком (слой, который строит URL, где ошибка
выглядит не как красный тест, а как 404: необязательный catch-all, знак процента
не как экранирование, query строкой и объектом, ошибки конфигурации; закрыта
непокрытая половина Next-плагина — алиас webpack, при поломке которого сервер не
загрузит конфиг запроса и приложение упадёт во время работы; подтверждено, что
объявления typegen совпадают с тем, что реально разрешает рантайм; и поправлена
ошибка прошлого отчёта: `LocalizedLink` покрыт браузерным гейтом CI, а не
«нулем тестов» — вывод был сделан по `grep` только по каталогу `test/`), V13 закрыт целиком (маскер разбора исходников — самый
опасный кусок библиотеки, потому что его ошибка не бросает исключение, а делает
живой ключ мёртвым, — проверен на девятнадцати входах, включая кавычку внутри
регулярного выражения, и закрыт тестами; README обещал список всех непроверяемых
мест вызова, а инструмент молчит там, где переводчик приходит из пропсов: граница
описана и закреплена тестом, а поведение оставлено — оно было выбрано сознательно;
удалён внутренний экспорт, которым никто не пользовался), V12 закрыт целиком (`FluentErrorCode` обещал диагностику
`ENVIRONMENT_FALLBACK`, которую библиотека не может выдать никогда, — код удалён,

## Как читать проход

1. **Резюме** — сколько находок и сколько исправлено.
2. **Методика** — какие команды реально прогонялись: без этого списка отчёт
   невозможно проверить.
3. **Находки по приоритетам** — P1 (неверный результат / блокировка сценария),
   P2 (архитектура и функциональные пробелы), P3 (качество, доки, гигиена).
   У каждой — воспроизведение, а не описание.
4. **«Что проверено и оказалось в порядке»** — список атак и проверок, которые
   устояли: его нужно перечитывать перед следующим проходом, чтобы не искать
   то же самое дважды.
5. **Изменения прохода** — какие файлы правились и чем это проверено.
