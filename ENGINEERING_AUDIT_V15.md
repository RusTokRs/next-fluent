## 1. V15-01. «Недостижимо в Node» было сказано про слишком многое

Отчёты V12 и V14 писали: `client.js` закрыть нельзя, нужен рендерер. Проверка
показывает, что нужен рендерер **только для `useEffect`** — а всё остальное
выполняется в `renderToStaticMarkup`:

| ветка | что это | раньше |
| --- | --- | --- |
| `client.js:85` | `messages`, переданные готовым бандлом | не выполнялась |
| `client.js:97` | то же для `fallbackMessages` | не выполнялась |
| `client.js:101-102` | `fallbackBundles`: один бандл против массива | не выполнялась |
| `client.js:239-241` | `<FormattedMessage className>` без компонента | не выполнялась |

Всё поведение верно:

- готовый бандл вместо исходного текста используется как есть, и предупреждений
  о непрочитанных записях нет — незачем, если парсить было нечего;
- **один** `fallbackBundles` принимается наравне с массивом (это и есть
  нормальный вызов из серверного компонента: массив там не собирается);
- бандл фолбэка той же локали работает — обычная раскладка «одна локаль на
  несколько файлов»;
- `className` без компонента даёт `<span class="…">`, а не теряется: это заметная
  ошибка, потому что `<input {...t.attrs('field')} className="x" />` — типичный
  вызов, и потеря класса видна только в вёрстке;
- отсутствующее сообщение не отменяет разметку вызывающего: `<span class="x">greet</span>`.

## 2. V15-02. Место вызова раньше своего переводчика

`collectCallSites` ищет ближайшее **предшествующее** связывание имени, а когда
вызов стоит раньше — берёт единственное связывание файла. Этот запасной путь не
выполнялся.

```jsx
export function Card() {
  const label = t('alpha');   // вызов раньше объявления t
  const t = useTranslations();
  return label;
}
```

→ ключ `alpha` использован, `missing` не выдан. И с выражением
(`t(row.key)`) → `dynamic`. Обе половины зафиксированы: первая особенно важна,
потому что неизвестный namespace не должен превращаться в провал сборки.

## 4. Что осталось в `client.js` и почему это решение, а не отложенное

Непокрыты `27-28` (мемоизация стабильных функций, нужна повторная отрисовка),
`155-159` (`useTimeZone` с откатом), `181-190` (два `useEffect` в `useNow`).

Ни один из них не выполняется без рендерера, запускающего эффекты. Вариантов
три, и выбор сделан в пользу отказа:

1. **Писать проверку в браузерный гейт CI.** Единственное место, где контекст
   есть. Но локально гейт не запускается, а логи упавшей задачи из этой среды
   недоступны: отдаёт их с блоб-хоста, которого нет в списке разрешённых. То
   есть отладка была бы вслепую.
2. **Добавить `jsdom` в зависимости разработки.** Даёт настоящие эффекты, но
   это ~10 МБ в дереве разработки и отладка `act()` с React 19 — инфраструктура,
   а не библиотека. Такое решение стоит принимать владельцу репозитория, а не
   вплетать в аудит молча.
3. **Не трогать.** Тринадцать строк в одном модуле, из них две — эффект
   обновления часов, а третья — стабилизация ссылок на функции.

Оставшиеся тринадцать строк записаны здесь явно, чтобы следующий проход не
начинал с них заново и не выдавал их за новую находку.

## 6. Приоритеты следующего прохода

1. **`useNow({ updateInterval })` и смена локали в `useFormatter`** — единственное
   непроверенное поведение с реальным пользовательским смыслом. Закрывать либо
   браузерным гейтом, либо решением по `jsdom` (см. §4).
2. **`usage.js`, остаток (93.3 % ветвей).** Незакрытые ветви — недописанный
   аргумент, незакрытое регулярное выражение, незакрытая скобка: это обработка
   мусора, а не поведение.
3. **`rich.ts`, `bundle.ts` (97.2 % / 96.1 % ветвей).** В V8 проверена
   безопасность разметки; при текущей частоте проходов имеет смысл перечитать
   ветви, а не строки.
4. **Полный перечень непокрытого — не приоритет сам по себе.** Три прохода подряд
   показывают одно и то же: оставшиеся ветви — либо защита, либо браузер. Дальше
   имеет смысл искать не по покрытию, а по сценариям, которых ещё не пробовал
   никто: сторонние `Host`, кэширующие CDN, `basePath` в сочетании с
   доменами, два независимых Next-приложения за одним reverse proxy.
