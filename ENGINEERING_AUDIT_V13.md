## 1. V13-01 (P2). Документация обещала больше, чем делает инструмент

**Воспроизведение.** README, таблица находок:

> `dynamic` | `t(key)` или `` t(`x-${id}`) `` — unverifiable statically, listed for review

На практике:

```jsx
export function Row({ t, row }) { return <span>{t(row.key)}</span>; }
```

`collectCallSites` возвращает **ноль** мест вызова: имя `t` в этом файле не связано
ни с одной фабрикой, а `src/usage.ts:708` пропускает такой вызов целиком —
`if (!known && staticString(argument) === undefined) continue;`.

**Это не дефект кода.** Пропуск намеренный и закреплён тестом
`analyze_usage`: `const t = 5; t(3)` не должен попадать в отчёт, а имя длиной в
одну букву, вызванное с переменным аргументом, переводом может и не быть.
Проверка форсирует тот же результат: в файле, где фабрика есть **выше** вызова,
` t(row.key)` честно попадает в `dynamic`; где фабрики нет — нет.

**Дефект в другом.** Граница не была написана нигде. Человек, прочитавший README,
ожидает список всех непроверяемых мест вызова и не получает их — и не понимает,
почему. У документации есть конкретное обещание («listed for review») и нет
оговорки.

**Исправление.** README, раздел `--usage`: абзац «Where a call site is listed as
`dynamic`…» — правило целиком, включая то, почему `const t = 5; t(3)` молчит, и
почему литеральный ключ через неизвестный переводчик попадает в `dynamic`, а не
в `missing`. Тест `a non-literal key is listed only where the translator is known`
фиксирует ту же границу со стороны кода.

Правка была бы и в коде, если бы не существовало уже принятое решение против
неё: расширить правило значит начать сообщать о `t(setTimeoutRef)` в чужих
файлах, а под `--strict-usage` это ещё и провал сборки. Документация приведена в
соответствие с поведением, которое было выбрано сознательно.

## 2. V13-02 (P3). Экспорт, которым никто не пользуется

`clearCatalogIntegrityWarnings()` был экспортирован из `src/catalog-integrity.ts`,
**не выходил ни в одну публичную точку входа и не вызывался нигде**: ни в `src/`,
ни в тестах. У его собратьев (`clearFormatterCache`, `clearFunctionsCache`) есть
публичные выходы и тесты.

Удалён. Поведение не изменилось: набор «уже сообщённых каталогов» и сам
по себе ограничен (`MAX_WARNED_CATALOGS`), поэтому утечки не было и удаление
ничего не ломает. Вместо теста на удалённую функцию — тест на её отсутствие:
предупреждение о битом каталоге приходит один раз на источник, а при 260 разных
битых каталогах — ровно 260 раз, то есть ограничение действительно работает.

## 3. V13-03 (P3). Маскер: девятнадцать входов, ни одного теста

`maskNonCode` — самый опасный кусок библиотеки. Ошибка в нём не бросает
исключение: она просто делает невидимыми все места вызова после точки, где
разбиратель ошибся, и ключ, который переводят на каждом рендере, попадает в
`unused`.

Всё проверено пробником **до** того, как писались тесты. Результат: nineteen из
девятнадцати входов разобраны верно, включая классику, которая ломает
самописные разборы:

| вход | результат |
| --- | --- |
| `const r = /['"]+/g;` — кавычка внутри регулярного выражения | следующие ключи найдены |
| `const r = /ab+/gi;`, `/a\/b/g`, `/[/]/g` | разобраны как регулярные выражения |
| `const x = a / b;` | деление, не регулярное выражение |
| `return /x/.test(y)` | регулярное выражение после `return` |
| `` t(`${fn('x')} key`) ``, `` t(`${ {a:1}.a }`) ``, `` t(`${a['b']}`) `` | `dynamic`, не выдуманный ключ |
| `const s = 'it\'s fine';` | кавычка не завершает строку досрочно |
| недописанный файл: `'oops`, `` `oops ``, `/oops`, `t({` | ключ, прочитанный до поломки, на месте |
| `// it's … t('ghost')` и `/* t('ghost') */` | комментарий не изобретает место вызова |

Правок кода не потребовалось — потребовалась защита от регрессии. 13 тестов.

## 4. V13-04 (P3). Две команды и три контракта

- **`checkCatalogs({})`** возвращает пустой отчёт, а не падает — публичная функция,
  вызываемая из программного API.
- **`pseudoLocalizeFtl`** для сообщения, кончающегося переменной
  (`greet = Hello { $name }`): закрывающая скобка псевдолокализации встаёт после
  placeable отдельным текстовым элементом; сообщение, состоящее только из
  переменной, не меняется; атрибуты обрабатываются так же, как значения.
- **Анализ без каталогов** возвращает пустой отчёт и при этом всё ещё перечисляет
  литеральные места вызова для ручного просмотра.
- **`t.attrs()` на сообщении, у которого есть только атрибуты**, разрешается и
  считается отрисованным — раньше эта ветка не выполнялась ни разу.
- **Ссылка на несуществующую опорную локаль** отвергается с указанием, какие
  локали анализировались.

## 6. Приоритеты следующего прохода

1. **`LocalizedLink` (0 тестов) и `useNow({ updateInterval })`.** Живой
   клиентский контур: браузерные прогоны CI — единственное место, где контекст
   App Router существует. Проверять там, а не в Node.
2. **`client.js` (70.2 % ветвей), `navigation.js` (59.5 %).** Оставшиеся ветви —
   `useEffect`/`useMemo` и делегаты роутеру; закрывать тем же способом.
3. **`usage.js` (92.6 % ветвей).** Осталось то, что не придумать руками:
   `scanStringLiteral` на недописанном аргументе, `skipRegex` без закрывающего
   слэша, чтение аргументов с незакрытой скобкой.
4. **`route-engine.ts`, `alternate-links.ts`, `nav-url.ts`.** Не разбирались в
   этом проходе: ветвей мало, покрытие высокое, но там строятся URL, а
   неправильный URL — это не «красный тест», а 404 у пользователя.
