## 3. V24-01. Вотчер, который молча ничего не смотрел

`watchCatalogs` умеет две стратегии. С `unref` — поллинг: снимок каталога
сравнивается каждые 300 мс, потому что рекурсивный `fs.watch` на Linux держит
event loop и не даёт `next build` завершиться. Без `unref` — `fs.watch`.

Проверка «является ли цель каталогом» стояла **после** ветки `unref`:

```ts
if (handlers.unref) {
  let signature = catalogSnapshot(input);
  const poller = setInterval(…);
  return () => { … };        // ← выход до всякой проверки
}

let stats = fs.statSync(input, { throwIfNoEntry: false });
if (!stats?.isDirectory()) { handlers.onError?.(…); return …; }
```

Плагин Next.js (`src/plugin.ts`) передаёт `unref: true` **всегда** — иначе
`next build` не завершится. Значит, для плагина проверка не выполнялась никогда.

Что это давало на практике. Измерено: `writeTypeDeclarations` принимает на вход
**файл**, а не только каталог —

```
writeTypeDeclarations('<dir>/en.ftl', out) → ok: ["<dir>/en.ftl"]
```

поэтому `typegen: { input: 'messages/en.ftl' }` выглядел рабочим: типы
генерировались, конфиг возвращался, ошибок не было. Дальше вотчер получал тот же
путь, `catalogSnapshot` на файле давал пустую строку (ошибка `readdir`
проглатывается), снимок никогда не менялся — и вотчер не делал ничего, не сказав
ни слова. Ровно тот класс отказов, который эта серия ищет: тихий.

**Исправление.** Проверка перенесена выше обеих стратегий, с комментарием,
почему она обязана быть до ветки `unref`, а не только до `fs.watch`.

**Контроль.** С проверкой на прежнем месте тест V24-07 падает:

```
not ok 10 - V24-07: typegen pointed at a single file still reports the dead watcher
ok остальные 11
```

С перенесённой — 12/12.

## 4. V24-02. Функция, которую выдавало соотношение 100 / 88.89

Невызванной оказалась стрелка внутри `sameSource`:

```ts
function sameSource(a, b) {
  if (typeof a === 'string' || typeof b === 'string') return a === b;
  return a.length === b.length && a.every((item, index) => item === b[index]);
}
```

Строковые источники — обычный случай — уходят в первую строку, и до `every`
дело не доходит. Массив источников в тестах передавался ровно один раз
(`advanced-features.test.mjs`), то есть **без повторного вызова**, а `sameSource`
вызывается только при попадании в кэш. Поэтому тело не выполнялось ни разу,
хотя строка была «покрыта» объявлением.

Закрыто тестом на повторный вызов с тем же массивом: кэш обязан вернуть **тот
же** объект бандла, а не собрать новый.

```
без audit-v24:  cache.js  100.00 строки / 94.00 ветки / 88.89 функции
с audit-v24:    cache.js  100.00 строки / 100.00 ветки / 100.00 функции
```

Заодно закреплено свойство хеша, ради которого в `computeSourceHash` есть шаг с
байтом-разделителем: `['ab','c']` и `['a','bc']` — одинаковые символы, одинаковая
суммарная длина, одинаковое число элементов — обязаны хешироваться по-разному.
Без разделителя оба дали бы один ключ, и бандл от одной разбивки отдавался бы
другой.

## 5. V24-03. Плагин: 60 % функций

Пять функций, три вызывались. Тесты покрывают: фабрику и обёртку, хук `webpack`
с пользовательским хуком и без него (в обоих случаях алиас проставляется до
передачи дальше), сохранение чужих `turbopack.resolveAlias`, генерацию типов по
каталогу, отказ генерации (пути вывода через файл) и регенерацию по изменению
каталога.

Последняя — единственная, которой нужен настоящий тик поллера: 300 мс интервал
плюс 50 мс debounce. Ожидание в тесте взято с запасом (1200 мс), потому что
тест, соревнующийся с собственным вотчером, хуже отсутствия теста.

Отдельно измерено и зафиксировано тестом: **нечитаемый вход не бросает**.
`collectCatalogFiles` проглатывает ошибку `readdir` и возвращает пустой список,
поэтому «сломать» генерацию через вход нельзя — только через вывод. Это и
определило форму теста V24-08; первая его версия использовала `__filename`,
которого в ES-модулях нет.
