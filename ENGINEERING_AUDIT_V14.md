## 1. V14-01. Ошибка в отчёте V13, найденная за один шаг

§6 отчёта V13 предлагал первым пунктом «`LocalizedLink` (0 тестов)». Число было
верным — в Node-тестах его действие не выполняется ни разу, — но вывод из него
нет. `grep` смотрел только на `test/`, а покрытие этой компоненты живёт в
`scripts/test-next-integration.mjs`:

```jsx
// test/fixtures/next-app/app/[locale]/client.tsx
<Link href="/about" locale="en">Switch to English</Link>
```

```js
// scripts/test-next-integration.mjs
const link = /link "Switch to English" \[ref=([^\]]+)\]/.exec(snapshot);
run('click', link[1]);
if (!after.includes('/about-us') || !after.includes('About route')) { … }
if (!run('cookie-get', 'NEXT_LOCALE').includes('NEXT_LOCALE=en')) { … }
```

То есть покрыт именно тот случай, который опасен: ссылка с явной локалью,
гидрация в браузере, переход по клику, URL, cookie и отсутствие ошибок в
консоли. Непокрытым остаётся мелочь — решение о `prefetch` и пересылка ref.

Чтобы это рассуждение не потерялось и чтобы связь нельзя было порвать случайно
(удалить ссылку из фикстуры — и никто не заметит), добавлен тест, который
проверяет саму фикстуру и сам гейт. Отрицательный контроль: удаление `<Link>` из
компонента роняет его.

## 2. V14-02. Маршруты, которые не проверены никем

`route-engine.ts` превращает `pathnames` в URL. Проверено пробником, всё верно,
включая то, что легко принять за дефект:

| вход | результат |
| --- | --- |
| `/docs/[[...slug]]` без значения, с `[]`, с `['a']`, с `['a','b']` | `/docs`, `/docs`, `/docs/a`, `/docs/a/b` |
| `/docs/[...slug]` без значения | ошибка с именем `slug` |
| `/x/[id]` со значением-массивом | ошибка `Expected one route parameter: id` |
| `/a/[...rest]/b` | `/a/x/y/b` — сегменты вокруг сохраняются |
| `/sale/50%` | `/sale/50%25` — знак процента, не являющийся экранированием, переживает туда-обратно |

Последнее — единственное место, где ошибка выглядела бы как 404: `decode`
падает на `%`, и если бы сегмент брался как есть без перекодирования, ссылка, по
которой кликнули, и маршрут, который сопоставляет сервер, разошлись бы.

Ошибки конфигурации (`pathnames` не абсолютны, `//evil.com`, дубликаты с
регистром, переименованный параметр, `basePath` с `/` в конце, без `/`, с `?`,
с `#`) — все отвергаются с сообщением, которое читают один раз при сборке.

## 3. V14-03. Как приложения на самом деле передают href

| вход | результат |
| --- | --- |
| `{ pathname: 'about' }` — без ведущего слэша | `/about` |
| `{ pathname: '/about', query: '?a=1&b=2' }` | `/about?a=1&b=2` |
| `{ pathname: '/about', query: 'a=1' }` | `/about?a=1` |
| `{ pathname: '/about', query: 'a=1&a=2' }` | повторяющиеся ключи сохранены |
| `{ pathname: '/about', query: { a: 1, b: null, c: undefined, d: [1,2] } }` | `/about?a=1&d=1&d=2` |

Последняя строка — не косметика: значение `null` без фильтра превратилось бы в
текст `null` в адресной строке.

## 4. V14-04. Половина Next-плагина и согласованность typegen с рантаймом

**Webpack.** Алиас Turbopack покрыт с V2. Функция `webpack` — целиком непокрытая,
и это путь, при поломке которого `next-fluent/config` не резолвится в сборке с
webpack: сервер не загрузит конфиг запроса, и приложение упадёт **во время
работы**, а не на сборке. Теперь проверено: абсолютный алиас для webpack,
цепочка с пользовательской функцией, сохранение чужих алиасов, создание
`resolve`/`alias`, если их не было.

**Typegen против рантайма.** Обещание типизированного API — «`t('unknown')` не
компилируется» — держится только если объявления и бандл согласны. Именно это и
проверено: ключи, объявленные typegen, прогоняются через настоящий
`createTranslator`, и ни один не должен дать ошибку разрешения. Попутно
подтвердилось найденное при пробе: при двух каталогах, определяющих `nav`,
позднее определение вытесняет раннее целиком — атрибуты не сливаются. Рантайм
ведёт себя так же (`t('nav.title')` → `MISSING_MESSAGE`), значит объявления
правы, и «слияние» было бы ошибкой typegen, а не исправлением.

## 6. Приоритеты следующего прохода

1. **`client.js` (70.2 %) и `navigation.js` (59.5 %).** Оставшиеся ветви —
   `useEffect`/`useMemo` и делегаты роутеру. Схема, которая себя оправдала в
   этом проходе: покрывать там, где контекст существует, а отсутствие покрытия
   фиксировать гейтом на саму фикстуру, чтобы оно не исчезло молча.
2. **`useNow({ updateInterval })` и `useFormatter` при смене локали.** Живой
   клиентский контур; в Node не воспроизводится, в CI — да.
3. **`usage.js` (92.6 %).** Осталось то, что не придумать руками: недописанный
   аргумент, незакрытое регулярное выражение, незакрытая скобка.
4. **`middleware.ts` (98.9 % строк).** Разбирался в ранних проходах; при
   возросшем внимании к остаткам стоит перечитать построчно — это код, который
   отвечает за то, какой URL вообще попадёт в адресную строку.
