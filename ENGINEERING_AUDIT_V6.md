## 2. P1 — результат разрешался на другом origin (исправлено)

### V6-01. Обратные слэши превращали внутренний путь в protocol-relative href (исправлено)

**Приоритет:** P1. `resolveLocalizedPathname` нормализует `\` в `/`
(Windows-разделители), но ведущий запуск слэшей после этого никто не сворачивал.
`normalizeLeadingSlashes` применялась только к остатку после снятия префикса
локали — то есть к тому пути, где префикс *нашёлся*. В режимах `as-needed`
(для дефолтной локали) и `never` префикс не подставляется, и результат уходил
в `<a href>` как есть.

```js
// до
resolveLocalizedPathname({ href: '/\\evil.example' }, asNeeded)  // '//evil.example'
new URL('//evil.example', 'https://my.example').href             // 'https://evil.example/'
```

Тот же путь открывался после снятия `basePath`: `/app/\evil.example` → вырезание
`/app` → `//evil.example`. В режиме `always` и для не-дефолтных локалей дефект
маскировался подставленным префиксом (`/en//evil.example` — уже same-origin).

**Исправление.** Ведущий запуск разделителей сворачивается сразу после
нормализации разделителей и снятия `basePath` — до сопоставления с префиксом
локали, поэтому покрыты все режимы и все формы входа (`src/nav-url.ts`).
`//host` по-прежнему обрабатывается как внешний URL: строковый href
возвращается как есть, объектный — отклоняется (`URL object pathname must be an
internal path`).

```js
// после
resolveLocalizedPathname({ href: '/\\evil.example' }, asNeeded)  // '/evil.example'
```

**Тесты:** `V6-01` (2 теста) — все режимы, `basePath`, внешние формы, объектная форма.

### V6-02. `port` объектного href не проверялся — подмена хоста (исправлено)

**Приоритет:** P1. `absoluteUrlFromObject` валидирует `hostname`/`host`
(запрещает `/`, `?`, `#`, `@`, `\`, пробелы) и протокол, но `port` подставлялся
в строку как есть. `@` в порту переписывает *authority*: строка
`https://example.com:@evil.com/a` разбирается как userinfo `example.com:` плюс
хост `evil.com`.

```js
// до
absoluteUrlFromObject({ pathname: '/a', hostname: 'example.com', port: '@evil.com' })
// 'https://example.com:@evil.com/a' → new URL(...).host === 'evil.com'
absoluteUrlFromObject({ pathname: '/a', hostname: 'example.com', port: '80/../x' })
// 'https://example.com:80/../x/a' — мусорный href, который URL-парсер затем отвергает
```

**Исправление.** Порт обязан быть числом (1–5 цифр), иначе — понятная ошибка;
`resolveLocalizedPathname` с таким объектом тоже падает, а не молча уезжает на
чужой хост (`src/nav-url.ts`).

```js
// после
absoluteUrlFromObject({ pathname: '/a', hostname: 'example.com', port: '3000' })  // '...:3000/a'
absoluteUrlFromObject({ pathname: '/a', hostname: 'example.com', port: '@evil.com' })
// throws: [next-fluent] URL object port must be numeric (received "@evil.com").
```

**Тесты:** `V6-02` — числовые порты (строкой и числом), IPv6-хост с портом,
пять отвергаемых форм.

## 3. P2 — молча неверный результат (исправлено)

### V6-03. Невалидный `timeZone` молча превращал даты в ISO-строки (исправлено)

**Приоритет:** P2. `createFormatter` кэширует форматтеры, а на исключении
конструктора `Intl.DateTimeFormat` возвращал `date.toISOString()`. Опечатка в
`requestConfig.timeZone` (`'Not/AZone'`, `'Europe/Mins'`) или несовместимая пара
опций давали в UI машиночитаемую строку — без предупреждения и без лога:
2000 вызовов → 2000 `2026-01-02T03:04:05.000Z`, ноль сообщений.

**Исправление.** Неизвестная зона сообщается один раз на `локаль::зона`
(набор ограничен, как у неизвестных форматов) и **повторяется без зоны**, то
же самое с остальными опциями: текст остаётся локализованным, а не превращается
в ISO. Форматтер-заменитель кладётся в тот же кэш, поэтому горячий путь не
платит за ошибку конфигурации (2000 вызовов — 23.6 мс).

```js
// после
createFormatter({ locale: 'en', timeZone: 'Not/AZone' }).dateTime(d)  // '1/2/2026'
// console.warn: [next-fluent] Unknown time zone "Not/AZone" (see `requestConfig.timeZone`); using the runtime zone.
```

**Тесты:** `V6-03` (3 теста) — зона из конфига, зона в опциях вызова, валидная
зона молчит, `clearFormatterCache()` сбрасывает дедупликацию.

### V6-04. BOM в начале каталога съедал первую запись (исправлено)

**Приоритет:** P2. Ни `@fluent/bundle`, ни `@fluent/syntax` не считают U+FEFF
пробелом: файл, сохранённый редактором с BOM (Windows-инструменты, часть
генераторов каталогов), молча терял **первое** сообщение — и только его.
`JSON.parse` BOM снимает сам, `fs.readFileSync(path, 'utf8')` — нет.

```js
// до
new FluentResource('\uFEFFfirst = One\nsecond = Two').body.map(e => e.id)  // ['second']
createFluentBundle('en', '\uFEFFfirst = One').getMessage('first')          // undefined
parse('\uFEFFa = A')                                                       // [Junk, …]
```

**Исправление.** Метка снимается в общей воронке: `stripCatalogBom` в
`src/catalog.ts` вызывается в `getCachedFluentBundle` и `getOrCreateResource`
(рантайм, включая `disableCache`), в `parseFtl` (типы, `pickMessages`, pseudo,
`check` — иначе инструменты ругались бы на каталог, который рантайм читает) и в
`readCatalog` (JSON-каталоги CLI). Хеш каталога считается уже без BOM, поэтому
обе записи одного файла делят одну запись кэша.

```js
// после
createFluentBundle('en', '\uFEFFfirst = One').getMessage('first')  // Message
getOrCreateResource('\uFEFFx = X') === getOrCreateResource('x = X') // true
```

**Тесты:** `V6-04` (3 теста) — рантайм, кэш ресурсов, инструменты и JSON-файл
через `readCatalog`.

### V6-05. Записи, выброшенные парсером рантайма, были невидимы (исправлено)

**Приоритет:** P2. `FluentResource` собирает только то, что понял: сообщение с
синтаксической ошибкой исчезает **без ошибки, предупреждения и следа**
(«Don't report any Fluent syntax errors»), а `addResource` возвращает пустой
список ошибок. Разработчик видел `MISSING_MESSAGE` для ключа, который в каталоге
написан, — самая частая причина «перевод есть, а не работает».

```js
// до
const bundle = createFluentBundle('en', 'good = Ok\nbad = { $x -> [one] one }');
createTranslator(bundle)('bad')  // 'bad' + MISSING_MESSAGE; ни одного сообщения о причине
```

**Исправление.** `src/catalog-integrity.ts` сверяет объявления записей
(`^id =` в начале строки — тот же якорь, что у парсера) с разобранным телом
ресурса и называет потерянные id; предупреждение выводится один раз на каталог.
Скан может переоценить только внутри уже выброшенного блока и не срабатывает на
каталогах, которые разбираются полностью (продолжения, атрибуты, варианты,
термины, дубликаты — проверено тестом).

```js
// после
forLocale('en', { messages: 'good = Ok\nbad = { $x -> [one] one }' })
// [next-fluent] The en catalog contains 1 entry the Fluent parser cannot read, so it is missing
// at runtime: "bad". Run `next-fluent check` for the full report.
```

**Почему модуль серверный.** Клиентский бандл — продуктовое ограничение, а в
приложении на Next каталог впервые разбирается на сервере (`forLocale`,
`getTranslations`, `getMessages`) — там же, где уместно предупреждение. Если бы
скан жил в `cache.ts`, он стоил бы 836 B клиентского минифицированного бандла
(замерено); перенос в серверный модуль сохранил диагностику и не тронул бюджет.
Клиентские сценарии, где каталог приходит только в браузер, по-прежнему
получают `MISSING_MESSAGE` через `onError`.

**Тесты:** `V6-05` (2 теста) — предупреждение с id через `forLocale`, полный
каталог молчит.

### V6-06. `FluentType` из второй копии пакета не работал, а обычный объект давал невнятную ошибку (исправлено)

**Приоритет:** P2. `buildFluentArgs` пропускал значения «по форме»
(`'value' in v && typeof v.valueOf === 'function'`), но `@fluent/bundle`
принимает только `instanceof` **своей** `FluentType` и на чужой объект отвечает
`TypeError: Variable type not supported` → сообщение падало с `FORMATTING_ERROR`
вместо того, чтобы отформатироваться. Комментарий обещал поддержку второй копии
пакета, которой не было; заодно под ту же проверку попадали обычные данные
(`{ value: 1 }`), и вместо `INVALID_ARGUMENT` с именем аргумента разработчик
получал невнятный `FORMATTING_ERROR`.

```js
// до (значение — FluentNumber из второй копии @fluent/bundle, класс с valueOf, обычные данные)
t('v', { x: new FluentNumber(5) })          // 'v' + FORMATTING_ERROR
t('v', { x: { value: 5, valueOf: () => 5 } }) // 'v' + FORMATTING_ERROR
t('v', { x: { value: 1 } })                 // 'v' + FORMATTING_ERROR
```

**Исправление.** Значения, у которых есть `value` и **собственный** `valueOf`
(чужая `FluentType`, value-объект приложения), разворачиваются в примитив,
который форматирует наша копия; обычные данные больше не притворяются
Fluent-значениями и попадают в `rejected` с понятным
`INVALID_ARGUMENT` и именем аргумента (`src/bundle.ts`).

```js
// после
t('v', { x: new FluentNumber(5) })            // 'Value: 5'
t('v', { x: { value: 12, valueOf: () => 12 } }) // 'Value: 12'
t('v', { x: { value: 1 } })                    // 'v' + INVALID_ARGUMENT (имя аргумента в cause)
```

**Тесты:** `V6-06` (2 теста) — чужая форма, value-объект, своя `FluentNumber`,
обычные данные.

## 4. P3 — исправлено

### V6-07. Снапшот конфига перетирал локаль запроса (исправлено)

`getRequestConfigSnapshot(locale)` писал локаль снапшота в request-store.
Снапшот — побочный запрос (общий виджет, `FluentServerProvider` с явной
локалью), и после него `getLocale()` в том же рендере начинал возвращать чужую
локаль. Теперь store сохраняет локаль, которую уже разрешил запрос
(`store.locale ??= locale`), а `timeZone`/`now` по-прежнему берутся из снапшота —
именно их читают синхронные `getNow()`/`getTimeZone()`.

Проверяется не только юнит-тестом: динамическая страница фикстуры
(`test/fixtures/next-app/app/[locale]/live/page.tsx`) берёт снапшот для другой
локали и печатает локаль до и после; интеграционный скрипт требует
`data-snapshot-locale="en"` и `data-scope-locale-after-snapshot="ru"` внутри
русского запроса — на Next 15.5.26 и Next 16.4.0. Реальный request scope даёт
только RSC-сборка React, `react-dom/server` в юнит-тестах его не создаёт, поэтому
e2e-часть живёт в фикстуре.

**Тесты:** `V6-07` (юнит: снапшот отдаёт запрошенную локаль и заполняет
`timeZone`/`now`) + интеграционные проверки `/live` и конкурентного батча.

### V6-08. Циклические опции `Intl` роняли рендер (исправлено)

`stringifySorted` (ключ кэша форматтеров) рекурсировал по объекту без защиты от
циклов: `formatter.number(5, cyclicOptions)` → `RangeError: Maximum call stack
size exceeded` прямо в рендере. Теперь сериализация идёт по пути объекта и
подставляет `"[circular]"`.

**Тесты:** `V6-08`.

### V6-09. Домен, записанный с точкой в конце, не находился (исправлено)

`example.com.` — абсолютная форма того же хоста; библиотека нормализует её везде
(`findDomain`, `trustedHosts`, request host), кроме одного места — поиска домена
в middleware. Конфигурация `domains: [{ domain: 'example.com.' }]` молча не
применялась: запрос к `example.com.` обрабатывался глобальными правилами
(например, глобальным `localePrefix: 'always'` вместо доменного `'never'`).

**Тесты:** `V6-09` — запрос к `https://example.com./docs` обслуживается (200, без
`Location`), потому что доменная настройка применилась.

## 5. Что проверено и оказалось в порядке

Проверялось пробниками на `dist/`, ниже — то, что **не** потребовало правок:

- **`catalog.ts` / JSON-каталоги.** Круг «JSON → FTL → разбор» байт в байт:
  многострочные значения, атрибуты (`{"": "…"}`), переменные `{name}`/`{$count}`,
  литеральные скобки `\{ \}`, строки, начинающиеся с `.`/`#`/`*`/`[`, `=`,
  `-term`, `}` — всё либо экранируется, либо остаётся текстом; правило
  `^[.#*[]` и обёртка в строковые плейсхолдеры держат инъекцию (проверено
  разбором через `@fluent/syntax` и рантайм-парсер).
- **`route-engine.ts`.** Приоритет шаблонов (статический > одноразовый >
  catch-all > optional, терминатор выше), `decode`/`encodeURIComponent` в
  параметрах, `validatePathnames` (дубликаты, разный набор параметров),
  `validateRouteEnvironment` (basePath, домены, префиксы).
- **`nav-url.ts`.** Абсолютные URL и `#`-ссылки, снятие `basePath`, поиск по
  `pathnames` с `query`-параметрами шаблона, `switchLocaleHref` (сигнальный URL,
  кросс-доменные переключения), `rewriteToInternalPath` (фолбэк по чужим локалям).
- **`pick-messages.ts`.** Транзитивные ссылки (сообщение → термин → термин),
  самоссылка без дублирования, порядок вывода, ошибка на `Junk` своего namespace.
- **`typegen.ts`.** Разрешение ключей совпадает с `buildKeyCandidates`
  (включая V5-06), перекрытые атрибуты описываются комментарием, дубликаты id —
  last-wins, как в рантайме.
- **`pseudo.ts`, `usage.ts`, `check.ts`, `bin/next-fluent.mjs`.** Разбор
  вложенных плейсхолдеров и строковых литералов, маскирование кода (regex,
  шаблоны, комментарии), коды выхода CLI, `--strict-usage`.
- **`middleware.ts`.** Стратегии `never`/`as-needed`/`always` с `pathnames`,
  сигнальный rewrite с токеном процесса, `Vary`, cookie-политика
  (`localeDetection: false`), `trustedHosts` с wildcard и loopback-правилом,
  кросс-доменные редиректы.
- **`cache.ts` / `lru.ts` / `functions.ts`.** Дедупликация ресурсов по содержимому,
  кэш бандлов с кастомными функциями (WeakMap + поколение), `unwrapFluentValue` в
  `CURRENCY`/`PERCENT`, падение Intl-конструктора не ломает рендер.
- **`errors.ts` / `client.ts` / `server.ts`.** Контракт `onError` /
  `getMessageFallback` (исключение в обработчике не ломает рендер),
  `defaultTranslationValues`, `useStableFunctions`, `useNow` без `now`,
  `forLocale` с явными сообщениями и фолбэками.

### Бюджет клиентского бандла

Правки этого прохода — не косметика: валидация порта, сворачивание слэшей,
разворачивание чужих Fluent-значений и защита от циклов живут в клиентском
графе, поэтому бюджет поднят **осознанно** и с замером, как в прошлых проходах

## 8. Приоритеты для следующего прохода

> **Все четыре пункта ниже закрыты проходом V7** — см.
> [`ENGINEERING_AUDIT_V7.md`](./ENGINEERING_AUDIT_V7.md): браузерная диагностика
> каталога под `NODE_ENV` (§2), бюджет клиента переведён на фикстуру
> потребителя (§3), V5-06 зафиксирован как правило вместо долга (§4),
> `publish.yml` проверен `actionlint` и полным `npm publish --dry-run` (§5).
> Абзацы оставлены как история: они описывают состояние на момент V6.

Открытых дефектов прохода V6 нет. Что стоило сделать дальше:

1. **Клиентский бюджет снова тонкий (0.3 kB min / 0.4 kB gzip).** Следующая
   правка клиентского графа, скорее всего, потребует не поднимать бюджет, а
   сузить публичную поверхность корневого энтри: `dist/index-browser.js`
   реэкспортирует `./utils` и `./catalog` целиком, поэтому в клиент попадают
   `resolveAcceptLanguage` и `jsonToFluent` независимо от использования. Это
   API-решение (ломает импорты из корня), поэтому в этом проходе не сделано.
2. **V5-06 как симптом.** Перекрытие «сообщение `a-b` против атрибута `a.b`»
   описано типами и комментарием, но атрибут по-прежнему недостижим через `t()`
   (только `t.attrs()`). Правило разрешения в `buildKeyCandidates` придётся
   пересматривать вместе с форматом ключей JSON-каталогов.
3. **Диагностика каталога — серверная.** Каталог, который попадает только в
   браузерный бандл (без серверного разбора), предупреждения о выброшенных
   записях не получает; если это понадобится, нужен dev-механизм, который
   вырезается из продакшн-сборки (`process.env.NODE_ENV`), — сейчас такой код в
   клиентском модуле стоил бы байтов в бюджете.
4. **Проверить workflow публикации вживую** — `publish.yml` написан, но ни один
   релиз через него ещё не проходил; первый dry-run (`workflow_dispatch`) должен
   остаться отдельной задачей.
