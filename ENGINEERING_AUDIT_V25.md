## 1. Почему потребовался другой инструмент

Оба модуля показывали **100 % строк при ~72 % веток**. Текстовый отчётчик в такой ситуации
не говорит ничего: непокрытое плечо `a ?? b` лежит на строке, которая выполняется. Поэтому
целевые строки взяты не «на глаз» по исходникам, а из сырых данных V8:

```
NODE_V8_COVERAGE=/tmp/v8cov node --test "test/*.test.mjs"
```

дальше скрипт для каждого диапазона берёт срез кода в его середине и смотрит счётчик
**самого внутреннего** диапазона, его содержащего (диапазоны V8 вложенные: диапазон с
нулевым счётчиком всегда лежит внутри функции с ненулевым — наивный «есть ли хоть один
покрывающий» даёт ложный «всё покрыто», я на это попался с первой попытки).

Важная оговорка: для вложенных `??` этот способ показывает поддиапазоны, которые
выраженческий отчётчик считает покрытыми. Ниже я разделяю «измерено как непокрытое» и
«сырой V8 флагует поддиапазон».

## 3. `factory.js` — что было непокрыто

Не вызывались почти все методы, которые возвращает `createI18n`:

| Метод | Форма вызова | Тест |
| --- | --- | --- |
| `getStaticParams()` | — | V25-08 |
| `forLocale(locale, …)` | строка-namespace **и** объект опций | V25-09 |
| `getTranslations(…)` | `{ locale }`, голая строка, без аргумента | V25-10 |

| рантайм **без** `loadMessages` | ветка `if (config.loadMessages)` → `getServerMessages` | V25-14 |

V25-11 не просто проверяет «функция вернулась»: он сравнивает вывод `number(1234.5)` для
`ru` и `en` и требует различия — иначе тест проходил бы и на заглушке.

## 4. Что я сознательно НЕ стал выдавать за находку

Рантайм, созданный **без `loadMessages`** и при не вызванном `setRequestConfig`, молча
возвращает пустой каталог. Измерено:

```
getMessages      -> returned ""
forLocale        -> returned function   // и она вернёт ключ вместо текста
getTranslations  -> returned function
getFormatter     -> returned object
```

Соблазн был объявить это дефектом («молчаливая деградация»), но это ровно то, что
задокументировано: `defaultMessageFallback` рендерит ключ. Предупреждение в момент
`createI18n()` давать нельзя — `setRequestConfig` модуль-глобальный и может быть вызван
позже, так что предупреждение было бы ложноположительным. Поэтому V25-14 **фиксирует
измеренное поведение**, а отчёт не раздувает его до находки.

## 5. Остаток — честно

* **`factory.js`, `locale ?? config.defaultLocale` внутри `requestConfig`** (строка 14
  сборки). Все вызывающие (`forLocale`, `getTranslations`, `getFormatter`) передают уже
  разрешённую локаль, так что плечо по умолчанию недостижимо через публичный API. Это
  защитный код; **тестом не закрыто и закрывать насильно не стал**.
* **`navigation.js`, цепочка `options?.locale ?? currentLocale ?? defaultLocale`** — сырой V8
  флагует вложенные поддиапазоны на строках 62/72/86 и `?.locale`/`&& config.domains` на 82.
  При этом V25-05/06/07 вызывают `push`/`replace`/`prefetch` **без опций**, то есть путь
  через `?? currentLocale` реально выполняется, и выраженческий отчётчик поднял модуль с
  72.92 % до 95.16 %. Полностью разрешить поддиапазоны вложенных `??` моим скриптом я не
  смог, поэтому считаю авторитетным выраженческий отчётчик и **не подгонял** остаток
  искусственными тестами.
* `prefetch` намеренно **не** применяет `switchLocaleHref` — это V16-03, а не пропуск.
