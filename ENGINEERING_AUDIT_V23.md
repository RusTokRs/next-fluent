## 3. V23-01. Предупреждение, которое не может сработать

`src/cache.ts` собирал бандл так:

```ts
const errors = bundle.addResource(resource, { allowOverrides: true });
if (errors && errors.length > 0) {
  console.warn(`[next-fluent] Warnings adding FTL resource for locale ${locale}:`, errors);
}
```

V22 записал это как «несогласованный гейтинг»: `warnAboutDroppedEntries` gated
по `NODE_ENV`, а это — нет. Проверка показала, что вопрос не в гейтинге: **ветка
недостижима**. В `@fluent/bundle` у `addResource` ровно два `errors.push`, и оба
закрыты условием `allowOverrides === false`:

```js
if (allowOverrides === false && this._terms.has(entry.id))    errors.push(…)
if (allowOverrides === false && this._messages.has(entry.id)) errors.push(…)
```

Библиотека всегда передаёт `true`. Прогон восьми каталогов — дубликаты id,
совпадение имени термина и сообщения, мусор, `select` без ветки по умолчанию —
не дал ни одного предупреждения, что согласуется с чтением кода.

**Решение.** Ветка удалена, на её месте комментарий с обоснованием и ссылкой на
то, где дубликаты действительно сообщаются (`warnAboutDroppedEntries` — там, где
каталог читается). Предупреждение, которое не может сработать, хуже отсутствия:
оно читается как диагностика, которая есть.

**Контроль — измерением, не упавшим тестом.** С возвращённой веткой
`cache.js` даёт 98.25 строк и непокрытые 85–86, а все 14 тестов прохода остаются
зелёными: падать нечему, ветка не выполняется. Поэтому обоснование удаления —
чтение `@fluent/bundle` и прогон, а не красный тест; утверждать обратное было бы
нечестно.

```
с веткой:   cache.js  98.25 строки, 92.31 ветки, непокрыты 85-86
без ветки:  cache.js 100.00 строки, 94.00 ветки
```

## 4. V23-02. Четырнадцать тестов на ветки, которых никто не касался

Каждая ветка оказалась достижимой через публичный API — нужен был только вход,
который никто не пробовал. Моков не понадобилось.

**Вотчер каталогов (`watchCatalogs`).** Три входа: файл вместо каталога,
несуществующий путь, циклический симлинк. Все три дают ровно один вызов
`onError` с сообщением `Cannot watch … it is not a directory`, и функция
остановки возвращается и работает даже при отказе.

Отдельно измерено, потому что первое предположение было неверным:

```
statSync(путь через файл, { throwIfNoEntry: false }) → не бросает, возвращает undefined
statSync(несуществующий путь, …)                     → не бросает, возвращает undefined
statSync(циклический симлинк, …)                     → бросает ELOOP
```

`throwIfNoEntry: false` глушит не только `ENOENT`, но и `ENOTDIR`, поэтому
единственный детерминированный способ попасть в `catch` — цикл симлинка.

**Обход исходников (`collectSourceFiles`).** Битый симлинк в дереве: скан не
падает, настоящий файл находится. Несуществующий корень скана: возвращает `[]`,
не бросая в вызывающий код — это покрывает и `realPathOrNull → null`, и `catch`
вокруг `readdirSync`.

**Чтение каталогов (`collectCatalogFiles`).** Битый симлинк на `.ftl`
пропускается, настоящий каталог выживает.

**`localePrefix.prefixes` не объект.** `'nope'`, `42`, `null`, `true` отклоняются
на старте; соседние корректные формы по-прежнему принимаются, так что проверка
не оказалась шире нужного.

**Некорректный тег локали.** `'not a tag!'`, `''`, `'!!!'`, `'en-'` не вылезают
наружу исключением: `new Intl.Locale` бросает, построитель кандидатов это
глотает, и запрос с мусорным заголовком деградирует в «не совпало», а не в 500.
Настоящий тег при этом продолжает совпадать.

**Неизвестный код ошибки.** `FluentError` с кодом вне перечисления даёт
`[next-fluent] Localization error for "common.greeting"`, а не `undefined` —
ветка для вызовов из простого JavaScript.

**Фолбэк, вернувший не строку.** `getMessageFallback` — пользовательский код, и
из JavaScript он может вернуть что угодно. `undefined`, `null`, `42`, `{}`, `[]`
деградируют в собственный фолбэк библиотеки; строка по-прежнему уважается.
Утверждение сравнивает с фактическим значением по умолчанию, а не с угаданным
форматом: первая версия теста проверяла `'en:absent'` и упала, потому что
реальный фолбэк печатает только ключ.

**`href` без ведущего слеша.** `resolveLocalizedPathname({ href: 'about' })`
даёт ровно тот же результат, что и `'/about'`, — `'/ru/about'`.

## 5. V23-03. Что осталось недетерминированным

Две ветки в `catalog-io.js` закрыть тестом нельзя, и это утверждение, а не
отговорка:

- **150–151** — `catch` в `catalogSnapshot`: `collectCatalogFiles` прошёл, а
  `fs.statSync` на отдельном файле упал. Это гонка «файл исчез между обходом и
  `stat`»; воспроизводится только удалением файла в нужный момент.
- **200–202** — `catch` вокруг `fs.watch`. Каталог к этому моменту уже проверен
  на `isDirectory`, поэтому `fs.watch` бросает только при исчерпании лимита
  inotify или отказе ядра — ни то, ни другое не воспроизводится по требованию.

Обе — защита от среды, а не логика. Их покрытие покупается ценой хрупкого теста,
которое будет падать на чужой машине; правильный ответ — оставить их
непокрытыми и сказать об этом.

обхода при битом симлинке, отклонение некорректных `prefixes` и деградация
фолбэка теперь закреплены.

**Три ошибки в самих тестах**, пойманные до коммита:

- `assert.match(строка, строка)` — второй аргумент обязан быть `RegExp`;
- имя теста `V23-12` было использовано дважды;
- формат фолбэка был угадан (`'en:absent'`) вместо того, чтобы быть измерен.
