## 1. V9-01 (P1). Бюджет размера охранял две секции из семи

**Воспроизведение.** `scripts/size-budget.mjs` бандлит один вход —
`test/fixtures/size/client-consumer.ts` — и в нём перечислены импорты. Защита от
того, чтобы список устарел, была ровно одна: тест в `test/audit-v8.test.mjs`,
сверяющий фикстуру с экспортами `dist/client.js` и `dist/navigation.js`. **Прочие
браузерно-достижимые точки входа не проверял никто**, а их было пять:

```
index-browser.js (next-fluent)          42 экспорта, из них в фикстуре 17
client.js / navigation.js / routing.js  покрыты
formatter.js                            clearFormatterCache — не импортируется
utils.js, catalog.js                    9 + 4 экспорта — не импортируются
```

Приложение, которое использует `jsonToFluent`, `matchSupportedLocale`,
`clearBundleCache` или `LRUCache` (всё это экспортируется из корня), отгружает
**49.63 kB** — больше, чем бюджет 48.5 kB, который гейт якобы охраняет. При этом
1.67 kB кода были достижимы из браузера и не учитывались **ни в одном** измерении.
Формулировка «фикстура импортирует весь документированный клиентский API, значит
всё, что может загрузить приложение, измеряется» была верна про документацию и
неверна про экспорты.

**Правка.** У гейта теперь две метрики с разным смыслом:

| метрика | что значит | вход |
| --- | --- | --- |
| **fixture** | что грузит приложение, использующее документированный клиентский API | рукописный файл, как раньше |
| **ceiling** | вообще всё, что может загрузить браузер | **генерируется из экспортов пакета** |

Потолок не написан руками: скрипт перечисляет браузерно-достижимые точки входа,
собирает из них временный вход (`export * from 'next-fluent'` и т. д.) и бандлит
его. Новый экспорт попадает в измерение в момент появления — рассинхронизировать
список руками нельзя. Сверка идёт по `metafile` esbuild: имена экспортов
сравниваются с реальными рантайм-экспортами тех же модулей, то есть потолок
проверяет сам себя.

**Проверка.** Бюджет потолка: **50.5 kB** при замере 49.63 kB (собственный код без
`@fluent/bundle` — 39.5 при 38.79). Отдельный тест требует, чтобы разница
потолка и фикстуры была заметной (>1 kB): равенство означало бы, что фикстура
снова покрывает всё, и метрика потолка стала бы второй копией первой.

## 2. V9-02 (P1). Фасад пакета существовал в двух экземплярах, и правился не тот

**Воспроизведение.** `src/index-browser.ts` и `src/index-server.ts` — фасады,
через которые работает корень пакета. Они транспилируются наравне со всеми
остальными модулями… и тут же **затираются** строковой константой
`sharedExports` в `scripts/build.mjs`. Проверено: правка фасада в `src/` не меняет
ничего в поставляемом пакете, и **ни один гейт этого не замечает** — `tsc`,
eslint, `check-dist` (сравнивает `dist/` с коммитом, а не с `src/`), тесты и
бюджет остаются зелёными.

**Правка.** Дубликат удалён: фасад пишется один раз, в `src/`, и транспилируется
общим шагом сборки. Проверено сравнением: набор экспортов и идентичность функций
корневых входов **до и после совпадают полностью** (`only old=[] only new=[]`,
`identity differs=[]`) — изменение чисто архитектурное.

Заодно в сборку добавлена проверка, которую не хватало по той же причине: closure
для CJS собирается сканом `from './x'` в `src/plugin.ts` и не видит ни
`export … from './x'`, ни `import('./x')`. Теперь после сборки каждый
относительный импорт в выводе проверяется на существование файла. Отрицательный
контроль: добавление `import './locale-prefix';` в `src/plugin.ts` останавливает
сборку с сообщением `dist/cjs/plugin.cjs imports "./locale-prefix.cjs", which was
not emitted` — вместо `MODULE_NOT_FOUND` в `next.config.js` у потребителя.

## 3. V9-03 (P2). `number` и `relativeTime` деградировали молча

**Воспроизведение.**

```
format.number(1234.5, { style: 'currency' })   -> "1234.5"   (тишина)
format.number(1234.5, { style: 'unit', unit: 'nope' }) -> "1234.5"  (тишина)
format.relativeTime(-3, 'day', { style: 'nope' })        -> "-3 day"  (тишина)
format.dateTime(date, { dateStyle: 'short', timeZoneName: 'short' })
   -> "1/2/2026, UTC" + предупреждение          <- проход 8 починил dateTime
```

`Intl.NumberFormat` бросает на `{ style: 'currency' }` без валюты (TypeError) и на
`{ style: 'unit', unit: 'nope' }` (RangeError); обработчик возвращал `String(value)`.
Результат неотличим от «правильного» числа: читатель видит `1234.5` и считает, что
валюта просто не нужна. Проход 8 ввёл правило «диагностика не угадывает причину,
но называет, что отказали» для `dateTime` — два соседних форматтера ему не
подчинялись.

**Правка.** Тот же контракт: одно предупреждение на пару (locale, набор опций) —
`Intl refused these number options for "en-US" (style); the value was rendered as
"1234.5".` Никакого спасения опциями не выдумывается: для чисел нет единственного
поля, удаление которого доказуемо является причиной, а молча выбрасывать опции
значит менять вывод так, как разработчик не просил. Сброс дедупликации — в уже
существующем `clearFormatterCache()`.

## 4. V9-04 (P2). То же на FTL-стороне, где ошибку увидеть нельзя в принципе

**Воспроизведение.**

```
ftl: bad = { CURRENCY($p, currencyDisplay: "nope") }   ->  "12.5 USD"
```

Здесь хуже, чем в форматтере. Функция вызывается внутри `formatPattern`, а
`formatPattern` сообщает только о том, что отверг сам Fluent; функция ловит свою
ошибку `Intl` сама и наружу не отдаёт ничего. Валюта не применилась, читатель
получил число с кодом валюты рядом — выглядит как осознанный формат.

**Правка.** Те же одноразовые предупреждения с перечислением аргументов
(`Intl refused the options of CURRENCY() for "en" (currencyDisplay=nope); the
value was rendered as "12.5 USD".`), дедупликация по набору аргументов, сброс — в
`clearFunctionsCache()`. Сам запасной вывод не менялся: он и раньше был
осмысленным, добавлена только диагностика.

## 5. V9-05 (P2). Пустой объект-сообщение исчезал из JSON-каталога

**Воспроизведение.**

```
{ greeting: 'Hi', todo: {} }   ->  "greeting = Hi\n"     todo исчез, без ошибки
{ a: {} }                      ->  ""                    пустой каталог
{ nav: { items: {} } }         ->  ""                    вложенный случай тот же
```

Пустой объект — это не сообщение с пустым текстом, а сообщение, которое ещё не
написано. Молчаливое выбрасывание давало каталог, в котором обращение к
`t('todo')` промахивается, — ровно тот класс ошибок, ради которого существует
анализатор использования. Соседние невозможные формы (`null`, массив) отвергаются
с указанием, что делать; пустой объект проходил молча.

**Правка.** Отказ с тем же уровнем подсказки: `JSON catalog value at "todo" is an
empty object. Every message needs a value (""), at least one attribute, or nested
messages.`

## 6. V9-06 (P3). FTL-стиль `.attr` отвергался с сообщением не о том

**Воспроизведение.** `{ login: { '': 'Sign in', '.label': 'Label' } }` →
`JSON catalog key "login..label" is not a valid Fluent message id`. Автор, который
переносит строку `.label = …` из FTL, получает ошибку про идентификатор сообщения.
Ключ с ведущей точкой не может быть ничем иным: `normalizeId` превращает точку в
дефис, а `-` не может начинать идентификатор, — то есть такой ключ раньше всегда
падал, и поддержка ничего не ломает.

**Правка.** Одна ведущая точка в позиции атрибута трактуется как его маркер.
В позиции вложенного сообщения (когда нет пары `""`, к которой атрибут крепится)
такой ключ по-прежнему отвергается — закреплено тестом, чтобы поддержка не
расползлась.

## 7. V9-07 (P2). Матрица CI сообщала версию Next вместо того, чтобы её проверять

**Воспроизведение.** Матрица устанавливает `next@^16`, шаг «Report the Next.js
version under test» печатает версию, и всё. Если установка не вступила в силу,
задание с меткой «Next 16» проверяет Next 15 и остаётся зелёным: утверждение о
поддержке соседней мажорной версии оказывается непроверенным. Класс сбоя не
гипотетический — проход 7 уже ловил ровно его (`npm_config_dry_run`, унаследованный
вложенной установкой, приводил к «успеху» без записи).

**Правка.** `NEXT_FLUENT_NEXT_MAJOR` передаётся в задание, а harness проверяет его
против реально разрешённой версии и падает при расхождении. Проверка стоит до
сборки Next, поэтому отрицательный контроль стоит две секунды:
`NEXT_FLUENT_NEXT_MAJOR=999` → `The fixture was asked to test Next 999 but
node_modules/next is 15.5.26. The matrix label would not match what was verified.`
Локальный `npm run test:next:16` проверяет себя сам: если задан
`NEXT_FLUENT_NEXT_VERSION`, ожидаемая мажорная версия выводится из него.

**Эпизод, который стоил отдельного теста.** Первая версия правки добавила в шаг
интеграции **второй** блок `env:` — YAML оставляет последний из одинаковых ключей и
не говорит об этом. CI упал за 0 секунд: не тест, а синтаксис workflow. Хуже того,
если бы GitHub оказался снисходительнее, `NEXT_FLUENT_BROWSER` — флаг браузерного
прогона — тихо исчез бы из задания, и браузерная регрессия перестала бы
выполняться без единого красного сигнала. Теперь оба workflow разбираются в тесте
парсером, который отказывается считать дубликаты (`js-yaml`, добавлен в
devDependencies), и тест отдельно требует, чтобы у шага интеграции остались **оба**
переключателя. Отрицательный контроль: тот самый второй `env:` воспроизводится
намеренно — тест падает с `duplicated mapping key (99:9)`.

## 8. V9-08 (P3). У edge-бандла не было предела, а число считалось не в байтах

`scripts/check-edge-runtime.mjs` печатал `code.length / 1024` — это длина строки в
кодовых единицах UTF-16, а не байты: любой не-ASCII символ в бандле занижает
счёт. Предела не было вовсе, при том что middleware исполняется на каждом запросе.

**Правка.** Размер считается через `Buffer.byteLength` и сравнивается с лимитом
64 kB (замер — 40.6 kB). Это регрессионная черта, а не утверждение о платформе:
лимиты деплоя у платформ свои, а Next.js размер middleware только показывает.
Что проверяемо — что граф остаётся маленьким: импорт зависимости, которой в
middleware не место (парсер FTL сам по себе около 20 kB), пересекает черту и
превращает «middleware потяжелел втрое» из тихой деградации в красную сборку.
Тест собирает граф сам и проверяет и размер, и отсутствие парсера — свойство
защищено независимо от текста скрипта.

## 9. V9-09 (P3). `fnv1a64` отвечал 32-битным хешем

`fnv1a32` и его «обратно совместимый псевдоним» `fnv1a64` экспортировались из
`cache.ts`, а оттуда — через фасад — из корня пакета, то есть были частью
публичной поверхности. Псевдоним выполнял ту же 32-битную реализацию: имя
обещало 64 бита, ответ был 32. Ни одного использования, ни одного упоминания в
README, а пакет не публиковался ни разу — то есть «обратная совместимость» была
соглашением с несуществующим пользователем.

**Правка.** Обе функции стали внутренними. Экспорт корня по-прежнему содержит 42
имени; два из них перестали быть хешами.

## 10. Что проверено и оказалось в порядке

- **Правила конвертации JSON-каталогов.** Перебор 145 пар «валидный ключ ×
  значение» (кавычки, обратные слэши, `{}`, `#`, `*`, `[`, `=`, переводы строк, CR,
  tab, NUL, эмодзи, кириллица, пустая строка, пробелы по краям) дал **0**
  нечитаемых результатов; каждая невозможная форма отвергается с actionable
  сообщением.
- **Пробелы внутри фигурных скобок** (`{ name }` — не переменная) — задокументированное
  намеренное правило с обоснованием; менять его в проходе, который ищет дефекты,
  неправомерно, поэтому оно закреплено тестом как есть.
- **`typegen` против рантайма.** Каталог с атрибутами, селекторами, термами,
  пунктирными идентификаторами и теневыми атрибутами: для каждого сгенерированного
  ключа сверено, что рантайм требует ровно объявленные переменные — ни больше, ни
  меньше. Расхождений нет; пропущенная переменная честно даёт `FORMATTING_ERROR`
  через `onError`, а причина («Unknown variable: $amount») лежит в `cause`.
- **`getRequestConfigSnapshot` и синхронные помощники.** `store.now`/`store.timeZone`
  заполняются конфигом; опасный порядок (часы вперёд конфига) потребовал бы
  `generateMetadata`, отработавшего раньше layout-провайдера, — React рендерит
  родителя раньше детей, и построить такой порядок не удалось. Записано как
  непроверенное, а не как дефект.
- **Гейты умеют падать.** Отрицательные контроли: бюджет размера (все лимиты в 1
  байт → 6 нарушений, код выхода 1), `check-dist` (байт в `dist/utils.js` → код 1),
  покрытие фикстуры (удалён импорт `useMessages` → тест падает с именем),
  проверка импортов сборки, утверждение матрицы, edge-лимит.
- **Общий кэш бандлов.** `getCachedFluentBundle` отдаёт разделяемый изменяемый
  объект: это ловушка, но она общая с next-intl и устраняется только копированием,
  то есть уничтожением самого кэша. Оставлено как есть, записано здесь.

## 12. Приоритеты следующего прохода

1. **Покрытие `server.js` (75 % строк)** — самый непроверенный модуль библиотеки.
   Внутри него нужен настоящий request scope (`cache()` React'а), которого нет в
   Node-тестах; либо тестовый harness на `react-server-dom`, либо страница в
   интеграционной фикстуре Next, которая проверяет `getNow`/`getTimeZone` при
